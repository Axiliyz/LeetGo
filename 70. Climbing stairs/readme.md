## Задача

> You are climbing a staircase. It takes `n` steps to reach the top. Each time you can either climb `1` or `2` steps. In how many distinct ways can you climb to the top?

Сколькими способами можно подняться на `n` ступенек, если за один раз можно шагнуть на `1` или `2` ступеньки?

**Ссылка:** [leetcode.com/problems/climbing-stairs](https://leetcode.com/problems/climbing-stairs/)

---

## Инженерка

### Как додумался до решения

На листочке прогнал на маленьких числах вручную.

- `n=1` - 1 способ: `[1]`
- `n=2` - 2 способа: `[1,1]` `[2]`
- `n=3` - 3 способа: `[1,1,1]` `[1,2]` `[2,1]`
- `n=4` - 5 способов: `[1,1,1,1]` `[1,1,2]` `[1,2,1]` `[2,1,1]` `[2,2]`
- `n=5` - 8 способов `[1,1,1,1,1]` `[1,1,1,2]` `[1,1,2,1]` `[1,2,1,1]` `[2,1,1,1]` `[1,2,2]` `[2,2,1]` `[2,1,2]` 

**1, 1, 2, 3, 5, 8...** — это числа Фибоначчи. Вот и вся задача.

Почему? На ступеньку `n` можно попасть только двумя путями: шагнув с `n-1` (шаг на 1) или с `n-2` (шаг на 2). Значит количество способов добраться до `n` — это сумма способов добраться до `n-1` и `n-2`. Это и есть определение Фибоначчи.

---

### Первая попытка — рекурсия

Задача читается как рекурсия напрямую: `f(n) = f(n-1) + f(n-2)`.

```go
func climbStairs(n int) int {
    if n <= 1 {
        return 1
    }
    return climbStairs(n-1) + climbStairs(n-2)
}
```

Работает — но только на маленьких `n`. На `n=44` уже захлёбывается: дерево вызовов растёт экспоненциально, `f(n-1)` и `f(n-2)` пересчитывают одни и те же ветки снова и снова. `O(2ⁿ)`.

---

### Попытка вторая — рекурсия + мемоизация

Добавляем кэш: если уже считали `f(n)`, возвращаем готовое.

```go
var cache = map[int]int{}

func climbStairs(n int) int {
    if n <= 1 {
        return 1
    }
    if val, ok := cache[n]; ok {
        return val
    }
    result := climbStairs(n-1) + climbStairs(n-2)
    cache[n] = result
    return result
}
```

Уже `O(n)` по времени и памяти. Но стек вызовов всё ещё растёт, глобальный кэш — это плохой тон, и памяти тратим `O(n)` на хранение всех значений.

---

### Финальное решение — итеративный Фибоначчи

Нам никогда не нужны все `n` значений сразу — только два последних. Просто идём вперёд, сдвигая окно из двух переменных.

```
prev=1, curr=1
i=2: prev=1, curr=1+1=2
i=3: prev=2, curr=1+2=3
i=4: prev=3, curr=2+3=5
...
```

`O(n)` времени, `O(1)` памяти. Рекурсии нет — стек не растёт.

---

## Решение

```go
package main

import "fmt"

func climbStairs(n int) int {
	if n <= 1 {
		return 1
	}
	prev, curr := 1, 1
	for i := 2; i <= n; i++ {
		prev, curr = curr, prev+curr
	}
	return curr
}

func main() {
	fmt.Println(climbStairs(1))   // 1
	fmt.Println(climbStairs(2))   // 2
	fmt.Println(climbStairs(5))   // 8
	fmt.Println(climbStairs(12))  // 233
	fmt.Println(climbStairs(55))  // 139583862445
	fmt.Println(climbStairs(100)) // 573147844013817084101
}
```

---

## Разбор на примерах

| `n` | `prev` → `curr` трассировка          | Ответ |
| --- | ------------------------------------- | ----- |
| `1` | база                                  | `1`   |
| `2` | `(1,1)` → `(1,2)`                    | `2`   |
| `3` | `(1,2)` → `(2,3)`                    | `3`   |
| `4` | `(1,2)` → `(2,3)` → `(3,5)`         | `5`   |
| `5` | `...` → `(5,8)`                      | `8`   |

Последовательность: **1, 1, 2, 3, 5, 8, 13, 21...** — Фибоначчи со смещением на единицу.

---

## Сложность

|            | Сложность | Объяснение                                              |
| ---------- | --------- | ------------------------------------------------------- |
| **Время**  | `O(n)`    | Один цикл от 2 до n                                     |
| **Память** | `O(1)`    | Только две переменные `prev` и `curr`, никаких массивов |

---

## Эволюция решения

| Подход                   | Время   | Память | Проблема                              |
| ------------------------ | ------- | ------ | ------------------------------------- |
| Чистая рекурсия          | `O(2ⁿ)` | `O(n)` | Падает на `n≥44`, пересчёт веток      |
| Рекурсия + мемоизация    | `O(n)`  | `O(n)` | Глобальный кэш, глубокий стек вызовов |
| Итеративный Фибоначчи    | `O(n)`  | `O(1)` | ✓                                     |

---

## Что применял

- **Распознавание паттерна Фибоначчи** — ключевой инсайт: задача переформулируется как `f(n) = f(n-1) + f(n-2)`, и это сразу указывает на структуру решения
- **Скользящее окно из двух переменных** — вместо хранения всей истории значений держим только последние два; классический трюк для итеративного Фибоначчи
- **Параллельное присваивание** — `prev, curr = curr, prev+curr` обновляет обе переменные одновременно без временной переменной, Go позволяет это нативно
- **Мемоизация как промежуточный шаг** — важно понять, почему она улучшает рекурсию, прежде чем выбросить рекурсию совсем
