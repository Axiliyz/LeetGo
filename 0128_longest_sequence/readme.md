## Задача

> Given an unsorted array of integers `nums`, return the length of the longest consecutive elements sequence. You must write an algorithm that runs in `O(n)` time.

Найти длину самой длинной последовательности подряд идущих чисел (`1, 2, 3, 4`), даже если в исходном массиве они расположены не по порядку.

**Ссылка:** [leetcode.com/problems/longest-consecutive-sequence](https://leetcode.com/problems/longest-consecutive-sequence/)

---

## Инженерка

### Что за задача

```
nums = [100, 4, 200, 1, 3, 2]

В наборе чисел скрыта последовательность: 1, 2, 3, 4 — длина 4.
100 и 200 — одиночки, ни с чем не соединяются.

Ответ: 4
```

Важно: последовательность ищется по **значениям**, а не по позициям в массиве — числа могут идти в любом порядке.

### Первая идея — сортировка

Отсортировать массив, затем пройти один раз и считать длину текущей серии подряд идущих чисел, сбрасывая счётчик при разрыве.

```go
sorted := sort.Ints(nums)
current, res := 1, 1
for i := 1; i < len(sorted); i++ {
    if sorted[i] == sorted[i-1] {
        continue // дубликат
    } else if sorted[i] == sorted[i-1]+1 {
        current++
    } else {
        current = 1 // серия прервалась
    }
    res = max(res, current)
}
```

Работает, но это `O(n log n)` из-за сортировки

### Оптимальное решение — хеш-сет

Кладём все числа в `map[int]bool` (множество). Затем для каждого числа `n` проверяем: **является ли оно началом последовательности**? Число `n` — начало, если `n-1` не входит в множество. Если да — начинаем считать вперёд: `n+1`, `n+2`, ... пока числа есть в множестве.

```
set = {100, 4, 200, 1, 3, 2}

n=1:   set[0]? нет  - это начало! считаем: 1-2-3-4 (все есть), 5 нет - длина 4
n=4:   set[3]? есть - не начало, пропускаем
n=100: set[99]? нет - начало, но 101 нет - длина 1
n=200: set[199]? нет - начало, но 201 нет - длина 1
n=3:   set[2]? есть - не начало, пропускаем
n=2:   set[1]? есть - не начало, пропускаем

Максимум: 4
```

### Почему это `O(n)`, а не `O(n²)`

Кажется, что вложенный `for set[n+len]` создаёт квадратичную сложность — но это не так. Внутренний цикл запускается **только** для чисел, которые являются началом своей серии (`set[n-1] == false`). Каждое число в итоге проверяется внутренним циклом не более одного раза за весь алгоритм — суммарно по всем стартовым точкам набегает не больше `n` шагов. Это амортизированный `O(n)`.

### Магия `map[int]bool` без `ok`

В Go обращение к отсутствующему ключу в мапе возвращает zero value для типа значения. Для `bool` это `false` — поэтому `set[n-1]` без `v, ok := ...` уже корректно отличает «есть в сете» от «нет в сете».

---

## Решение

```go
func longestConsecutive(nums []int) int {
	set := make(map[int]bool, len(nums))
	for _, n := range nums {
		set[n] = true
	}

	res := 0
	for n := range set {
		if set[n-1] {
			continue
		}
		length := 1
		for set[n+length] {
			length++
		}
		res = max(res, length)
	}
	return res
}
```

## Разбор на примерах

| `n` (старт серии) | `n-1` в сете? | Считаем вперёд        | Длина |
| ------------------ | -------------- | ----------------------- | ----- |
| `1`                | нет - старт    | `1-2-3-4`, `5` нет     | `4`   |
| `100`              | нет - старт    | `101` нет               | `1`   |
| `200`              | нет - старт    | `201` нет               | `1`   |
| `4`, `3`, `2`       | да - пропуск   | —                        | —     |

Итог для `[100, 4, 200, 1, 3, 2]`: **4**

## Сложность

|            | Сложность | Объяснение                                                                |
| ---------- | --------- | -------------------------------------------------------------------------- |
| **Время**  | `O(n)`    | Заполнение сета `O(n)` + внешний цикл `O(n)` + внутренний цикл суммарно `O(n)` (каждое число проверяется один раз за весь алгоритм) |
| **Память** | `O(n)`    | `map[int]bool` хранит все уникальные числа                                |

| Подход            | Время        | Память | Плюсы                          | Минусы                              |

## Что применял

- **Hash Set для проверки принадлежности** — `map[int]bool` даёт `O(1)` проверку «есть ли число в наборе», без сортировки
- **Приём «искать только начала»** — считать длину серии только от чисел, у которых нет предшественника в множестве; это превращает потенциально квадратичный алгоритм в линейный
- **Zero value мапы вместо `comma-ok`** — `set[x]` для отсутствующего ключа возвращает `false` сам по себе, что упрощает условия
- **Амортизированный анализ сложности** — внутренний цикл выглядит как вложенный, но в сумме по всем итерациям внешнего цикла выполняется не больше `n` раз
