## Задача

> Given a string `s`, find the length of the longest substring without repeating characters.

Найти длину самой длинной **подстроки** (непрерывного куска строки), в которой все символы уникальны.

**Ссылка:** [leetcode.com/problems/longest-substring-without-repeating-characters](https://leetcode.com/problems/longest-substring-without-repeating-characters/)

---

## Инженерка

### Что за задача

```
s = "abcabcbb"

"abc" — без повторов, длина 3
"abca" — уже есть повтор 'a', не подходит
Ответ: 3
```

Важно — ищем именно **подстроку** (substring), то есть подряд идущие символы, а не произвольное подмножество, как в задачах на subsequence.

### Первая мысль — наивный перебор

Для каждой стартовой позиции `i` растягивать окно вправо до первого повтора, запоминая максимум. Это `O(n²)` или `O(n³)`, в зависимости от реализации проверки на повтор — слишком медленно для больших строк.

### Оптимальное решение — Sliding Window + последний индекс

Идея: держим окно `[start, i]` без повторов, и **карту** `map[rune]int`, где значение — индекс последнего вхождения символа. При встрече символа, который уже видели:

- если его последнее вхождение **внутри** текущего окна — окно обязано схлопнуться, начавшись сразу после этого вхождения
- если его последнее вхождение **уже вне** окна (устарело) — это не конфликт, окно просто растёт дальше

Чтобы не хранить отдельную переменную `start`, окно выводится через формулу: `winStart = i - cur`, где `cur` — текущая длина окна *до* обработки символа `i`.

```
s = "abba"

i=0 'a': не видели       → seen={a:0}, cur=1
i=1 'b': не видели       → seen={a:0,b:1}, cur=2
i=2 'b': видели на 1.
         winStart = 2-2 = 0.  1 < 0? нет → конфликт ВНУТРИ окна
         → окно схлопывается: cur = i - seen['b'] = 2-1 = 1
i=3 'a': видели на 0.
         winStart = 3-1 = 2.  0 < 2? да → старое вхождение, окно растёт
         → cur++ = 2

Ответ: max(1,2,1,2) = 2  ("ab" или "ba")
```

### Почему это сработало не сразу

Главная ловушка — **что делать с `cur` в каждой из двух веток**:

1. Конфликт внутри окна → `cur` нужно **пересчитать** как `i - seen[v]` (новая длина окна), а не оставить как было
2. Старое вхождение вне окна → `cur` можно просто **увеличить на 1** — никакого конфликта нет

Если забыть пересчитать `cur` в первом случае — окно не схлопывается и результат становится больше, чем должен быть (как было на `"abba"`, где код без этого исправления выдавал `3` вместо `2`).

Второй подводный камень — обновление `seen[v] = i` нужно делать **в обеих** ветках, не только в одной, иначе в карте остаётся протухший индекс и следующая проверка `seen[v] < winStart` сравнивается с неправильным числом.

## Решение

```go
package main

import "fmt"

func lengthOfLongestSubstring(s string) int {
	seen := make(map[rune]int)
	res := 0
	cur := 0
	for i, v := range s {
		if _, ok := seen[v]; !ok {
			seen[v] = i
			cur++
		} else {
			if seen[v] < i-cur {
				cur++
				seen[v] = i
			} else {
				cur = i - seen[v]
				seen[v] = i
			}
		}
		res = max(res, cur)
	}
	return res
}

func main() {
	fmt.Println(lengthOfLongestSubstring("abcabcbb")) // 3
	fmt.Println(lengthOfLongestSubstring("bbbbb"))     // 1
	fmt.Println(lengthOfLongestSubstring("pwwkew"))    // 3
	fmt.Println(lengthOfLongestSubstring("dvdf"))      // 3
	fmt.Println(lengthOfLongestSubstring("tmmzuxt"))   // 5
}
```

## Разбор на примерах

`"tmmzuxt"` — классический кейс, где старое вхождение проверяется на актуальность:

| `i` | `v` | `seen[v]` до | `winStart` | Конфликт? | `cur` после | `res` |
| --- | --- | ------------ | ---------- | --------- | ----------- | ----- |
| 0   | t   | —            | —          | новый     | 1           | 1     |
| 1   | m   | —            | —          | новый     | 2           | 2     |
| 2   | m   | 1            | 0          | внутри    | `2-1=1`     | 2     |
| 3   | z   | —            | —          | новый     | 2           | 2     |
| 4   | u   | —            | —          | новый     | 3           | 3     |
| 5   | x   | —            | —          | новый     | 4           | 4     |
| 6   | t   | 0            | 2          | устарело  | `4+1=5`     | **5** |

Ответ: `5` (подстрока `"mzuxt"`).

|            | Сложность | Объяснение                                                          |
| ---------- | --------- | --------------------------------------------------------------------- |
| **Время**  | `O(n)`    | Один проход по строке, каждый символ обрабатывается константное число раз |
| **Память** | `O(k)`    | `map[rune]int`, где `k` — размер алфавита (число уникальных символов в окне) |

## Сравнение подходов

| Подход                          | Время    | Память | Плюсы                                | Минусы                            |
| --------------------------------- | -------- | ------ | --------------------------------------- | ------------------------------------ |
| Наивный перебор всех подстрок     | `O(n²)`–`O(n³)` | `O(k)` | Просто придумать                       | Слишком медленно                  |
| Sliding window (наше)             | `O(n)`   | `O(k)` | Оптимально, один проход               | Легко ошибиться в пересчёте `cur` |

## Что применял

- **Sliding Window без явного `left`** — вместо отдельной переменной для левой границы окна, она выводится формулой `winStart = i - cur`, экономя одну переменную за счёт чуть менее очевидной логики
- **`map[rune]int` как «последний индекс»** — классический паттерн для substring-задач: карта хранит не факт присутствия, а **позицию** последнего вхождения, что позволяет отличить «актуальный» повтор от «устаревшего»
- **Различие двух типов повтора** — повтор внутри окна (требует схлопывания) и повтор вне окна (не требует никаких действий, кроме роста) — без этого разделения легко либо переусложнить, либо пропустить случай
- **`res = max(res, cur)` после каждой итерации, без `continue`** — любой досрочный выход из тела цикла рискует пропустить обновление результата на критичной итерации (особенно на последнем символе строки)
